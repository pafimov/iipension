# Backend

Дополняет корневой AGENTS.md.

- `pension/domain`: чистый Python, строгий mypy, Decimal, immutable dataclasses, без Django/ORM/HTTP/LLM и глобального времени.
- `schemas.py`: валидация на входе, явно ограниченные размеры, десятичные строки, запрет лишних полей. `api.py`: HTTP/права/транзакции; сложную бизнес-логику выносить в use-case/service.
- Модели не превращать в универсальный JSON-склад. Изменения схемы БД сопровождать штатной миграцией и проверкой существующих данных.
- Цели append-only: новая редакция — новый черновик, подтверждённые параметры не перезаписывать. При реализации FR-6 отдельно ввести версионирование расчётов.
- Использовать ORM и параметризованный SQL. Любая выборка личных объектов ограничивается владельцем; одного UUID недостаточно для авторизации.
- После схем: `make contract`. Сгенерированные файлы вручную не редактировать.
- `make backend-check`: Ruff + формат + mypy расчётного ядра + Django checks + отсутствие новых миграций + pytest с покрытием ≥85%. Остальной Django-код проверяют тесты и схемы; расширение mypy на ORM требует отдельной настройки stubs, оно пока не заявляется.
- Для PostgreSQL: `TEST_POSTGRES=1 POSTGRES_HOST=... POSTGRES_PASSWORD=... make backend-check` на отдельной тестовой БД. Тесты создают `test_<имя>`, нужны права создания БД. Никогда не направлять тесты в эксплуатационную БД.
- Тестировать формулы независимыми приёмочными числами, граничные случаи, отказы, ownership, CSRF, повторные действия и миграции. Не создавать тесты, которые только повторяют реализацию.
