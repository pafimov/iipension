# Реализация относительно исходных требований

Источники: нормализованные PRD/SRS/UserStories/RTM и roadmap в `sources/`, перечень и SHA-256 в `sources/manifest.json`. Это переданные владельцем требования, а не полностью готовый продукт. Исходный roadmap не переоценён и не помечен выполненным из-за создания каркаса.

| Требование / история | Статус шаблона | Код / проверка | Что дальше |
| --- | --- | --- | --- |
| FR-1 / US-1 | Частично: ручной ввод, owner-scoped сохранение, явное подтверждение; AI и запуск расчёта отсутствуют | schemas/api, GoalForm/GoalList; API input/ownership/CSRF + e2e | AI draft, вход в расчёт только после confirm; типизированные риск-ограничения |
| FR-2 / US-2 | Эталонное ядро, не подключено к продукту | domain/capital; тесты AC-2.1/2.2/2.4/2.5/2.6 | Инфляция AC-2.3, риск/terminal AC-2.7, снимок, налоги/расходы, результат/versions |
| FR-3 / US-3 | План | — | Net cash calendar, principal отдельно, completeness |
| FR-4 / US-4 | План | — | Stress и конечный капитал |
| FR-5 / US-5 | План | — | Три стратегии, общие ограничения, +10% только при положительной сопоставимой базе |
| FR-6 / US-6 | План; черновики уже не перезаписываются | Нет API обновления/удаления целей | Версии расчёта A/B и сравнение |
| FR-10 / US-10 | План | — | Объяснение результата и deterministic fallback |
| FR-7/8/9, US-7/8/9 | Следующий этап, не реализованы | Нет gateway/SDK/order routes | Consent, durable idempotency, reconciliation, stop/resume |
| NFR-1 | Частично на уровне ядра | Decimal, повторный тест | Полная повторяемость snapshot+rules+versions |
| NFR-2 | Интеграция отсутствует, соответствие sandbox не заявляется | Нет способов отправки заявок | Проверить полный набор AC после реализации sandbox |
| NFR-3 | План | — | Проверить цену и полноту по контрольному календарю |

Инфраструктурные гарантии каркаса (вне продуктовой RTM): auth/session/CSRF, фильтр owner, валидация ввода, login lockout, readiness, миграции, OpenAPI/type drift, lint/types/tests/build, переносимый запуск. Требовать ссылки на реальные тесты при каждом изменении статуса; не ставить «готово» по наличию заглушки.
