# Следующие задачи

Статус исходного roadmap сохранён отдельно как справочный; он не означает, что функции реализованы в этом шаблоне. Работать небольшими законченными ветками.

1. **Зафиксировать расчётные допущения** (FR-2/3/4/5, NFR-1/3). Уточнить формат и дату снимка, налоговую версию, риск/конечный капитал, валюту/оценку, правила стоимости и округления. Результат — ADR и схема fixture. Не ставить ставку доходности/налога по догадке.
2. **Валидатор снимка** (NFR-3.1–3.3). Цена каждого выпуска, обязательные события, контрольный календарь, лоты и costs. Ошибки с указанием выпуска/поля; месяц без купона отличается от пропущенного события.
3. **Расчётный use-case** (FR-2, FR-3). Инфляция today→start, допустимость корзины, reserve, versioned result, календарь с отдельным principal. Подключить ядро только к подтверждённой цели и валидному снимку. Повторяемость и immutable сохранённый результат.
4. **Экран результата и стресс** (FR-3/4). Полный календарь, первый/максимальный дефицит, база и стресс при одинаковом начальном резерве. Без LLM.
5. **Версии и сравнение плана** (FR-6). План A остаётся, изменение создаёт B; сравнение входов/результатов; никаких заявок.
6. **Протокол сравнения трёх стратегий** (FR-5/NFR-1). Одинаковые бюджет 1млн, риск, налоги, costs и конечный капитал; tie-break выпуском. 10% — проверка гипотезы с условиями, а не доходность пользователю.
7. **Отдельный AI-эксперимент** (FR-1/10). Только черновик + явное подтверждение, объяснение проверенных чисел с fallback, provider adapter, бюджет/таймауты, без персональных данных по умолчанию.
8. **Следующий этап: виртуальный счёт** (FR-7/8/9/NFR-2). Сначала threat model/контракт/приёмочные тесты. Durable consent + account + plan version + TTL, outbox/idempotency before network, reconcile/unknown lock, stop switch. Реальная торговля исключена; SDK не добавлять до отдельного поручения.

Исследование: 10–15 интервью с работающими людьми 25–40; M-2 (понимание взноса, первого дефицита и причины) первична. Наличие кода не подтверждает продуктовые метрики.
