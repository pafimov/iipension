# ADR-002: Деньги, округление и границы доверия

Статус: принято для эталонного ядра; полную модель расчёта ещё нужно согласовать.

- Money API принимает только десятичные строки с максимум двумя знаками после точки, не JSON number. На сервере Decimal, БД NUMERIC(16,2). Валюта первой версии RUB.
- В эталонной функции точность промежуточных операций 50 знаков. Доход начисляется на начало месяца, взнос — в конце. Промежуточный остаток не округляется каждый месяц; отображаемый капитал/дефицит округляются half-up до копейки, минимальный взнос — вверх. Это явная техническая политика для предоставленных примеров; при полном расчёте её необходимо утвердить с владельцем и версионировать.
- 0 месяцев означает сравнение с капиталом сейчас, required_monthly_contribution = None. Недопустимые ставки/отрицательные/нечисловые значения отклоняются.
- Начальный резерв — максимум положительного префиксного дефицита. Поступления тела долга не участвуют в этой функции.
- Не выбраны ставки доходности/инфляции, налоговый режим, состав бумаг, риск-лимиты, источники и дата снимка. Тестовые числа — приёмочные примеры, не рыночный прогноз. Верхняя граница UI 1200 месяцев — техническое ограничение размера ввода, а не рекомендация срока.
- Конечный финансовый результат обязан сохранять exact inputs + versions. Пока такого результата в БД/API нет, только черновик цели.
- Серверная сессия и CSRF, без токенов в browser storage; account provisioning вручную. Публичную регистрацию/восстановление/MFA/OIDC проектировать отдельной задачей. Production defaults требуют HTTPS и секрет >=50 символов; local compose не является production-конфигом.
- Защита входа django-axes: 5 ошибок, блокировка пары username + непосредственный peer-IP на час. За Nginx peer-IP общий: нужна ingress rate-limit политика и доверенная цепочка proxy, прежде чем менять извлечение IP. Нельзя слепо доверять клиентскому X-Forwarded-For.
