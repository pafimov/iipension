# Настройка Git-хостинга

Если вы распаковали ZIP, выполните `git init -b main` перед включением хуков и первым коммитом. Подготовьте пустой репозиторий на выбранном Git-хостинге, настройте его видимость, укажите URL как `origin` и отправьте ветку `main`. Для существующего клона используйте его настроенный `origin`.

Для GitHub уже есть `.github/workflows/ci.yml`. В настройках main/ruleset:

- запретить прямой push и force-push, требовать PR;
- обязательный status check **Quality / check**, актуальную ветку и разрешённые обсуждения;
- при работе командой хотя бы одного ревьюера на auth, money и migrations; вписать реальные handles в CODEOWNERS после выбора команды;
- включить squash merge и удаление завершённых веток; автоматический merge разрешать только после обязательных проверок;
- ограничить Actions permissions чтением по умолчанию, разрешения deployment отдельно; не передавать секреты fork PR;
- включить secret scanning/dependency alerts там, где доступны, настроить владельца уведомлений;
- Dependabot PR проходят те же проверки и не мержатся автоматически при изменении major-version.

На GitLab воспроизведите команды `make install`, `make check`, PostgreSQL service, контейнерный smoke и e2e в своём CI; логика проекта от хостинга не зависит. Файл GitHub Actions сам по себе не защищает основную ветку — эти настройки нужно включить на хостинге.

Локально `make hooks` включает простые проверки секрета/переносимости/формата коммита. Проверка переносимости содержит явный список разрешённых публичных HTTP-хостов/реестров; при подключении нового провайдера добавьте его после проверки в `scripts/check_portability.py`. Она не определяет публичность произвольного DNS автоматически. Хуки не заменяют полноценный secret scanner и удалённый CI. Не обходить хуки ради красной проверки.

Перед первым собственным коммитом задайте автора **локально для этого репозитория**:

```sh
git config user.name "Your name"
git config user.email "your-public-or-noreply-address"
```

Хук принимает заголовок `init` для корневого коммита. Для следующих коммитов действует Conventional Commits.
