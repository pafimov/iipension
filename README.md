# Личная пенсия — шаблон для разработки с ИИ-агентами

Независимый full-stack монорепозиторий: **Python 3.12 / Django 5.2 LTS / Django Ninja / PostgreSQL 17** и **React 19 / TypeScript strict / Vite**. Публичные зависимости, Docker Compose и проверяемые правила работы агентов. Разворачивается на своей машине или на выбранном вами хостинге.

Это **шаблон разработки**, а не готовый пенсионный советник. Уже работают вход по серверной сессии, сохранение личных целей, проверка ввода и отдельное подтверждение. Есть эталонные функции расчёта резерва и взноса с приёмочными примерами. Полный расчёт портфеля, данные рынка, календарь, ИИ и брокерские операции ещё не подключены. Подробный статус: [матрица требований](docs/product/traceability.md).

## Быстрый запуск

Нужны Docker Engine/Desktop с Compose v2, Python 3 для генерации локальных секретов и `make`.

```sh
make init-env             # создаёт .env с новыми случайными секретами, без вывода значений
make up                   # сборка, PostgreSQL, миграции, API, веб
make user                 # интерактивное создание своей учётной записи
```

Откройте **http://localhost:8080**. Укажите параметры личной пенсии, сохраните черновик и подтвердите его в разделе «Сохранённые планы». Данные сохраняются после обновления страницы. Готовых логинов/паролей нет. `createsuperuser` здесь используется как штатная интерактивная команда Django; административный веб-интерфейс не опубликован.

```sh
make logs
make down                # останавливает сервисы; данные в volume сохраняются
```

Не используйте `docker compose down -v`, если данные нужны. Первая сборка загружает публичные зависимости. Порт БД и API наружу не публикуется; веб по умолчанию слушает только loopback.

## Разработка и проверки

Установите Python 3.12, Node.js 24 LTS, [uv](https://docs.astral.sh/uv/getting-started/installation/) 0.13.9 и `make`:

```sh
make install             # uv.lock + package-lock.json
make check               # линтеры, формат, типы, тесты, сборка, миграции, API, переносимость
make hooks               # локальная защита коммитов; CI обязателен отдельно
make contract            # после изменения публичных схем
make format
```

Для hot reload и подключения IDE: [руководство разработчика](docs/development.md). Для браузерного теста задайте `E2E_USERNAME` / `E2E_PASSWORD` отдельной тестовой учётной записи, выполните `cd frontend && npx playwright install chromium`, затем `make e2e`. Тест создаёт цель в этой учётной записи, а не удаляет существующие данные. CI делает это на одноразовой БД и проверяет также PostgreSQL, контейнеры и интерфейс.

## С чего начать агенту

1. Прочитать [AGENTS.md](AGENTS.md), [архитектуру](docs/architecture.md) и [статус требований](docs/product/traceability.md).
2. Использовать [готовый стартовый промпт](docs/agent-workflow.md), выбрать одно требование и согласовать неизвестные финансовые допущения.
3. Работать в ветке, обновить тесты/контракт/документацию, выполнить проверки и сделать осмысленный коммит.

| Где | Назначение |
| --- | --- |
| `backend/pension/domain` | Чистое расчётное ядро: Decimal, никаких HTTP/БД/LLM |
| `backend/pension` | Модели, API, валидация и управление сессиями |
| `frontend/src/features` | Изолированные функции интерфейса |
| `frontend/src/shared/api` | Клиент и типы, сгенерированные из OpenAPI |
| `contracts` | Версионируемый API-контракт |
| `docs/product` | Требования из пяти исходных документов и честная трассировка |
| `docs/adr` | Причины архитектурных решений |
| `infra`, `compose.yaml` | Независимый локальный запуск |
| `.github`, `.githooks` | CI, шаблон PR, обновления зависимостей и локальные проверки |

Проведённые проверки и изображения интерфейса: [отчёт](docs/validation.md).

## Публикация и эксплуатация

Автоматического деплоя нет: [инструкция](docs/operations.md) описывает HTTPS, настройки окружения, миграции, резервные копии и откат. Публикация сервиса — отдельный шаг после выбора хостинга. Настройки защиты основной ветки включаются в вашем Git-хостинге, см. [репозиторий](docs/repository-setup.md).

Основа написана заново, без переноса исходников или истории другого сервиса. См. [сравнение вариантов стека и источники](docs/adr/001-stack.md). Лицензию приложения выбирает владелец.
